# 수동 검색에서 능동적 기억 탐색으로: 구조화된 행동 공간으로서의 장기 사용자 메모리 활용

## 저자의 문제 인식 및 주장 (15문장 이내)

1. 개인화된 대화형 에이전트는 여러 세션에 걸쳐 사용자의 정보와 선호를 기억해야 하지만, 기존 장기 메모리 시스템은 대체로 미리 검색된 정보를 수동적으로 제공하는 방식에 머물러 있다.  
2. 이러한 수동 검색 방식에서는 검색 결과가 불완전하거나 부정확해도 에이전트가 추가 증거를 직접 확인하기 어렵다.  
3. 사용자 정보는 사실, 사건, 지시, 선호, 장기적 주제 등 다양한 형태와 추상화 수준을 가지므로 하나의 메모리 표현이나 고정된 검색 전략만으로는 다양한 질의에 대응하기 어렵다.  
4. 저자들은 장기 사용자 메모리를 단순한 문맥(context)이 아니라 에이전트가 직접 탐색하고 선택하는 구조화된 행동 공간으로 다뤄야 한다고 주장한다.  
5. 이를 위해 NapMem은 원시 대화, 유형화된 메모리 기록, 주제별 추적 정보, 사용자 프로필로 구성된 다중 세분화 메모리 피라미드를 제안한다.  
6. 각 메모리 층은 출처 관계로 연결되어 있어 에이전트가 요약된 정보에서 구체적인 대화 증거로 내려가거나, 세부 정보에서 상위 수준의 맥락으로 올라갈 수 있다.  
7. 에이전트는 질의와 지금까지 확보한 증거를 바탕으로 어떤 메모리 수준을 확인할지, 추가 검색이 필요한지, 답변을 중단해도 되는지를 스스로 결정한다.  
8. 저자들은 메모리 도구 사용 궤적을 강화학습으로 최적화함으로써 메모리 활용 자체를 학습 가능한 정책으로 만든다.  
9. 실험 결과 NapMem은 개인화, 장기 회상, 세션 간 추론 등 다양한 메모리 중심 과제에서 경쟁력 있는 성능을 보였다.  
10. 동시에 메모리가 필요하지 않은 일반 추론 및 도구 사용 과제의 성능을 대체로 유지했으며, 불필요한 메모리 호출도 줄였다.  
11. 절제 실험은 다중 세분화 메모리 구조, 능동적 탐색, 강화학습 정책이 서로 결합될 때 성능 향상이 나타남을 보여준다.  
12. 따라서 장기 사용자 메모리의 효과적인 활용을 위해서는 정교한 저장 구조뿐 아니라 적절한 메모리 수준을 선택하는 학습된 탐색 정책이 함께 필요하다는 것이 논문의 핵심 주장이다.  
13. 다만 기존 벤치마크가 실제 개인화 상호작용을 모두 반영하지 못하며, 개인정보 보호와 잊힘(right to forget) 문제는 충분히 다루지 못했다는 한계가 있다.

## 주요 내용

### 1. NapMem의 기본 개념

NapMem은 “Navigate over Pyramid Memory”의 약자로, 사용자의 장기 대화 이력을 여러 추상화 수준으로 정리하고 에이전트가 도구를 통해 이를 능동적으로 탐색하도록 설계된 프레임워크다.

메모리 피라미드는 다음 네 층으로 구성된다.

- **원시 대화(Raw conversations)**: 메시지, 화자, 시간, 세션 정보 등을 보존하는 가장 상세한 증거 층이다.  
- **메모리 기록(Memory records)**: 대화에서 추출한 사실, 사건, 지시, 선호를 구조화한 compact한 정보다.  
- **주제 추적(Topic tracks)**: 여러 세션에 걸쳐 반복되거나 변화하는 주제를 통합한 중간 수준의 서술이다.  
- **사용자 프로필(User profile)**: 안정적인 사용자 특성, 장기 선호, 상호작용 패턴을 요약한 최상위 층이다.  

각 층은 출처 식별자로 연결되어 있어 상위 요약의 근거를 하위 대화나 기록까지 추적할 수 있다.

### 2. 메모리의 점진적 구축

사용자 대화는 시간 순서대로 처리된다. 새로운 대화는 먼저 원시 대화 층에 저장되고, 이후 메모리 기록으로 추출·통합된다.

기존 기록과 새 기록을 비교해 다음과 같은 작업을 수행한다.

- 새 정보 저장
- 중복 정보 삭제
- 오래되거나 잘못된 정보 업데이트
- 관련 정보 병합

변경된 기록은 주제 추적과 사용자 프로필에도 반영된다. 이를 통해 새로운 증거가 기존 기억을 확장하거나 수정하거나 반박할 때 상위 수준의 요약도 갱신된다.

### 3. 메모리 탐색 도구

NapMem은 다섯 가지 도구를 제공한다.

- `search_conversations`: 원시 대화에서 관련 메시지 검색
- `get_conversations`: 메시지 식별자로 특정 대화 조회
- `search_records`: 구조화된 메모리 기록 검색
- `get_records`: 기록 식별자로 특정 메모리 조회
- `read_files`: 주제 추적 파일이나 사용자 프로필 열람

에이전트는 넓은 사용자 프로필을 먼저 확인한 뒤 세부 기록이나 원시 대화로 내려갈 수 있으며, 반대로 구체적인 대화 검색에서 시작해 관련 주제 정보를 확인할 수도 있다.

### 4. 강화학습을 통한 탐색 정책 학습

에이전트는 질의마다 최대 네 번의 도구 호출 안에서 필요한 정보를 수집해야 한다. 강화학습에는 GRPO(Group Relative Policy Optimization)를 사용했다.

보상은 다음 요소를 반영한다.

- 답변 형식이 올바른가
- 답변이 정확한가
- 메모리 도구를 적절히 사용했는가
- 도구 호출 예산을 초과하지 않았는가

이 방식은 단순히 메모리를 많이 검색하도록 유도하는 것이 아니라, 정확한 답변을 위해 필요한 수준까지만 탐색하고 멈추는 행동을 학습하도록 한다.

### 5. 실험 결과

저자들은 다음 세 가지 메모리 중심 벤치마크에서 NapMem을 평가했다.

- **LoCoMo**: 장기간 대화 회상 및 세션 간 추론
- **LongMemEval**: 시간 변화, 장기 사실 회상, 선호 관련 질의
- **PersonaMem-v2**: 암묵적 사용자 선호와 페르소나 이해

Qwen3.5-9B에 강화학습을 적용한 NapMem은 세 벤치마크 평균 62.74점을 기록해 비교 대상 중 가장 높은 평균 성능을 보였다. 특히 LongMemEval과 PersonaMem-v2에서 최고 성능을 기록했고, LoCoMo에서는 F1 기준 최고 성능을 달성했다.

일반 추론과 도구 사용 능력을 평가한 GPQA-Diamond, BFCL-v3, V*Bench에서도 성능이 대체로 유지되거나 향상되었다. 일반 과제에서 불필요한 메모리 호출률은 강화학습 전 34.51%에서 6.90%로 감소했다.

### 6. 효율성과 행동 분석

NapMem은 여러 메모리 층을 유지하면서도 대부분의 비교 시스템보다 적은 저장 공간을 사용했다. 또한 필요한 증거를 확보하면 탐색을 종료하기 때문에 수동 검색 기반 시스템보다 응답 토큰 수와 지연 시간이 낮았다.

강화학습을 적용한 9B 모델은 평균 도구 호출 횟수가 3.97회에서 2.15회로 줄었지만, 여러 메모리 층을 사용하는 비율은 거의 유지했다. 동시에 검색 결과가 실제 정답 근거와 일치하는 비율은 20.66%에서 34.92%로 상승했다.

모델 규모에 따라 탐색 방식도 달랐다. 큰 모델은 사용자 프로필이나 주제 파일처럼 넓은 맥락에서 시작하는 경향이 강했고, 작은 모델은 메모리 기록이나 대화 검색처럼 구체적인 정보에서 시작하는 경향을 보였다.

### 7. 절제 실험과 한계

수동 검색만 사용하는 방식, 메모리 기록만 제공하는 방식, 상위 수준의 주제·프로필 층을 제거한 방식, 강화학습을 적용하지 않은 방식은 모두 전체 NapMem보다 성능이 낮았다. 이는 능동적 탐색, 다양한 메모리 수준, 학습된 정책이 함께 필요함을 보여준다.

사례 분석에서는 하위 수준 검색이 실패했을 때 주제 추적 정보가 정답을 복원하는 데 도움이 되는 사례가 확인되었다. 반면 사건에 관한 단일 기록을 사용자의 안정적인 선호로 과도하게 일반화하는 실패도 나타났다. 따라서 향후에는 사건, 일시적 행동, 지속적인 개인 선호 사이의 증거 강도를 더 정교하게 구분해야 한다.

논문은 실제 환경의 개인정보 보호, 메모리 삭제와 망각, 장기적이고 개방적인 개인화 상호작용을 충분히 다루지 못했다는 점을 한계로 제시한다.
