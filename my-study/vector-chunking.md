# 벡터와 청킹

## 1. 전체 흐름

```text
PDF → Document → 청킹 → 임베딩 → Vector Store → 유사도 검색 → LLM → 답변
```

## 2. 청킹(Chunking)

긴 문서를 **작은 조각(Chunk)**으로 나누는 것.

```text
긴 문서
 ↓
Chunk 1 | Chunk 2 | Chunk 3
```

문서 전체를 사용하는 대신 **질문과 관련된 부분만 검색**하기 위해 사용한다.

### 오버랩(Overlap)

청크 사이에 **이전 청크의 일부 내용을 겹쳐 넣는 것**.

```text
Chunk 1: [1][2][3][4][5]
Chunk 2:         [4][5][6][7][8]
```

청크 경계에서 문맥이 끊기는 것을 줄여준다.

* Chunk Size → 청크 하나의 크기
* Chunk Overlap → 청크 사이에 겹치는 내용의 크기

## 3. 임베딩과 벡터

**임베딩(Embedding)**: 텍스트를 숫자로 변환하는 과정

```text
텍스트 → Embedding Model → Vector
```

**벡터(Vector)**: 텍스트의 의미를 숫자로 표현한 것.

실제로는 수백~수천 차원의 벡터가 사용될 수 있지만, 개념적으로는 **2차원 좌표**처럼 생각할 수 있다.

```text
          ↑
          │       ● 문서 B
          │
          │  ● 질문
          │
          │ ● 문서 A
          └────────────────→
```

의미가 비슷한 텍스트일수록 벡터 공간에서 **가까운 위치**에 놓이도록 임베딩된다.

## 4. 유사도(Similarity)

질문과 문서의 **의미가 얼마나 비슷한지**를 나타내는 값.

```text
질문 ●
     │
     │ 가까움 → 높은 유사도
     ↓
문서 ●
```

따라서 Vector Store에서는 질문 벡터와 **유사도가 높은 문서 벡터**를 찾아 관련 Chunk를 가져온다.

```text
질문 Vector
     ↓
유사도 비교
     ↓
┌─────────────┐
│ 문서 A  0.91 │ ← 선택
│ 문서 B  0.73 │
│ 문서 C  0.21 │
└─────────────┘
```

## 5. Vector Store

벡터를 저장하고 검색하는 저장소.

실습에서는 **Chroma**를 사용한다.

```text
Chunk → Embedding → Vector → Chroma
                              ↓
질문 → Embedding → Vector → 유사도 검색
                              ↓
                         관련 Chunk
```

## 6. 핵심 정리

* **청킹** → 문서를 작은 조각으로 나누기
* **오버랩** → 청크 사이의 문맥을 이어주기
* **임베딩** → 텍스트를 숫자로 변환하기
* **벡터** → 텍스트의 숫자 표현
* **2차원 공간** → 벡터와 유사도를 이해하기 위한 간단한 표현
* **유사도** → 질문과 문서가 얼마나 비슷한지
* **Vector Store** → 벡터를 저장하고 검색하기
* **RAG** → 유사도가 높은 문서를 찾아 LLM의 Context로 제공하기

> **문서 → Chunk → Vector → 유사도 검색 → Context → LLM → 답변**

# 질문
## 1. 왜 문서를 Chunk로 나누는가?

긴 문서를 그대로 사용하는 대신 **작은 조각(Chunk)** 으로 나누어 사용한다.

``` text
긴 문서
 ↓
Chunk 1 | Chunk 2 | Chunk 3
```

### 왜 나누는가?

-   질문과 관련된 부분만 검색하기 위해
-   긴 문서를 한꺼번에 처리하는 부담을 줄이기 위해
-   필요한 문맥을 더 정확하게 가져오기 위해

### Chunk Size / Overlap

-   **Chunk Size** → 하나의 Chunk가 가지는 크기
-   **Chunk Overlap** → Chunk 사이에 겹치는 내용

Overlap을 사용하면 Chunk 경계에서 문맥이 끊기는 것을 줄일 수 있다.

## 2. 벡터와 유사도 검색은 어떻게 동작하는가?

텍스트는 **Embedding Model**을 통해 숫자로 변환되고, 이를 벡터라고 한다.

``` text
텍스트
 ↓
Embedding
 ↓
Vector
```

벡터는 개념적으로 **2차원 좌표**처럼 생각할 수 있다.

``` text
          ↑
          │       ● 문서 B
          │
          │  ● 질문
          │
          │ ● 문서 A
          └────────────────→
```

의미가 비슷한 텍스트는 벡터 공간에서 가까운 위치에 놓이도록 만들어진다.

따라서 질문을 벡터로 변환한 뒤, 저장된 문서 벡터와
**유사도(Similarity)**를 비교하여 관련 있는 문서를 찾는다.

``` text
질문 Vector
    ↓
유사도 비교
    ↓
관련도가 높은 Chunk 검색
```

## 3. RAG의 전체 흐름

RAG는 외부 문서에서 질문과 관련된 내용을 검색한 뒤, 이를 LLM의 Context로
제공하는 방식이다.

``` text
PDF
 ↓
Document
 ↓
Chunk
 ↓
Embedding
 ↓
Vector Store
 ↓
Similarity Search
 ↓
Context
 ↓
LLM
 ↓
답변
```

각 단계의 역할:

-   **Document** → PDF 등의 문서를 읽어온 데이터
-   **Chunk** → 문서를 작은 조각으로 분할
-   **Embedding** → 텍스트를 벡터로 변환
-   **Vector Store** → 벡터를 저장하고 검색
-   **Similarity Search** → 질문과 유사한 Chunk 검색
-   **Context** → 검색된 내용을 LLM에게 전달
-   **LLM** → Context를 바탕으로 답변 생성
